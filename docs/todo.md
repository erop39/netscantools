# NetInventory / netscantools — TODO: домашние фичи

Список идей сверх MVP + Planner + LAN Hygiene, отсортирован по приоритету (польза/сложность, от наивысшего к наименьшему). Для каждой — какую конкретно задачу она решает.

## Приоритет 1–4: сделать в первую очередь

- [x] **Wake-on-LAN** *(shipped)*
  Сложность: низкая · Польза: высокая
  **Решает:** устройство (NAS/ПК) выключено ради экономии электричества, а до него надо достучаться удалённо, не вставая с дивана и не идя физически включать. Кнопка на карточке устройства шлёт magic-пакет по MAC — доступ без физического присутствия.
  **API:** `POST /api/devices/{id}/wol` · UI: Device detail → Wake on LAN

- [x] **Автобэкап инвентаря** *(shipped)*
  Сложность: низкая · Польза: высокая
  **Решает:** вся база (устройства, история, план сети, чек-лист) хранится в одном SQLite-файле на локальной машине — при поломке диска/переустановке Windows всё пропадает без следа. Плановый экспорт БД в файл на расписании защищает от полной потери данных, накопленных за месяцы.
  **Settings:** `backup_interval_hours` / `backup_keep` · `POST /api/settings/backup-now` · files in `data/backups/`

- [x] **Комнаты/локации** *(shipped)*
  Сложность: очень низкая · Польза: средняя
  **Решает:** сейчас найти "что за штука висит в гараже" можно только через `notes` в виде текста — неудобно фильтровать и группировать. Отдельное поле "локация" + фильтр в списке ускоряет ориентацию, когда устройств становится много.
  **Field:** `Device.location` · filter `?location=` · `GET /api/devices/locations`

- [x] **Проверка TLS-сертификата** *(shipped)*
  Сложность: низкая-средняя · Польза: средняя-высокая
  **Решает:** устройства с HTTPS web-UI (роутер, NAS, камеры) могут иметь просроченный или самоподписанный сертификат — обычно узнаёшь об этом только когда браузер уже ругается. Проверка встраивается в существующий port-probe и security score, заранее подсвечивая проблему до того, как она мешает зайти в панель.
  **API:** `POST /api/devices/{id}/check-tls` · score penalties · Device detail TLS fact

## Приоритет 5–7: по желанию, когда будет время

- [x] **QR-код для web-UI** *(shipped)*
  Сложность: очень низкая · Польза: низкая-средняя
  **Решает:** чтобы открыть панель устройства с телефона, приходится вручную вбивать IP или искать ссылку — QR-код на карточке устройства ускоряет переход с мобильного, не решая при этом ничего критичного.
  **UI:** Device detail → QR · web UI

- [x] **Presence detection ("кто дома")** *(shipped)*
  Сложность: средняя · Польза: средняя
  **Решает:** сейчас появление/исчезание любого MAC в сети трактуется одинаково — а появление телефона члена семьи это не "новое устройство", а сигнал "человек дома/ушёл". Нужен отдельный флаг "это человек, не техника" и отдельная логика UX, не просто переиспользование существующих событий.
  **Field:** `is_person` · Home “Who’s home” · Devices `person` tag

- [x] **История latency** *(shipped)*
  Сложность: средняя · Польза: средняя
  **Решает:** сейчас хранится только последний замер RTT — деградацию роутера/сети ("стало тормозить за последнюю неделю") не видно, пока не станет совсем плохо. Минимальная история (последние N точек) позволяет заметить тренд раньше полного отказа.
  **API:** `GET /api/devices/{id}/latency-history` · samples on full scan

## Приоритет 8–9: только при конкретном поводе

- [ ] **Интеграция с Home Assistant**
  Сложность: средняя-высокая · Польза: условная (высокая при наличии HA, нулевая без него)
  **Решает:** дублирование трекинга присутствия/устройств в двух системах сразу (в NetInventory и в HA), если Home Assistant уже используется в доме. Вебхук на `new_device`/`went_offline` убирает необходимость отдельного трекера в HA. Делать только если HA реально есть.

- [ ] **Мультисеть/VLAN**
  Сложность: высокая · Польза: средняя, узкий кейс
  **Решает:** если роутер физически режет сеть на несколько зон (основная LAN + изолированная гостевая), одна настройка `scan_subnet` не покрывает весь дом — часть устройств просто не видна инвентарю. Требует переделки модели Settings/Scanner/Devices под несколько зон сканирования — самая дорогая фича в списке, делать только при реальном наличии нескольких физических сетей.
